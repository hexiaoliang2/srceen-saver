## 2. 应用跳转卡片

### 2.1 居中锚点
- 根 `Column` 固定 `width/height 100% + justifyContent(Center) + alignItems(Center)`；
- 横向档的内容组是一个 `Row`，由外层居中；文字列用 `constraintSize(maxWidth)` 限制宽度，**不用 `layoutWeight`**（`layoutWeight` 会把文字列撑满剩余宽度、把图标推到左侧；这是本轮实测发现并修掉的偏移根因）；
- 未使用任何条件 `top` 偏移、条件 `padding` 或按尺寸变化的偏移；
- 入口卡已从 `CardScrollView` 中移出：`Scroll` 内的百分比高度无法撑满格子，会导致内容组垂直偏上；移除后 `onAreaChange` 实测内容组在 1×2/2×2 都精确居中。

### 2.2 各档布局与图标比例（实测）

| 档位 | 布局 | 图标直径 : 内容区短边 | 名称 | 副标题 | 实测内容组占比 |
|---|---|---|---|---|---|
| 1×1 | 图标在上、名称/副标题在下 | 34 : 82 ≈ **41.5%** | L5 14 | L7 10 | 约 24%（随名称长度 20–27%） |
| 2×1 | 图标在左、文字列在右 | 36 : 104 ≈ **34.6%** | L4 16 | L6 12 | 约 18% |
| 1×2 | 竖向（图标/名称/副标题） | 36 : 82 ≈ **43.9%** | L4 16 | L6 12 | 约 12% |
| 2×2 | 横向居中 | 62 : 184 ≈ **33.7%** | L1 28 | L4 16 | **14.3%**（日志：group=97×54，content=184×199） |
| 3×3 / 4×4 | 横向居中 | 短边 × 0.34（上限 120） | L1 28 | L4 16 | 随面积增大继续下降 |

> 图标比例取 30%–45%：1×1 取 42%（小卡需要图标撑住视觉重量，仍低于 45% 上限），其余取 34%。实测日志：`entry group ratio 2x2: group=97x54 content=184x199 ratio=14.3% icon=62`。
>
> **70% 冲突报告**：入口卡是「一个图标 + 两行短文字」的居中组。2×2 内容区 184×199vp，组只有 97×54vp；即使把图标放到 45% 上限、文字放到 28fp，组面积也远不到 70%。要达到 70% 只能把文字拉伸/铺满或加底板，这会违反「内容组几何居中」「无底板」「不引入随尺寸变化的偏移」。因此按 §2.2 的最低优先级处理并在此报告，未隐藏副标题。

### 2.3 副标题
- 1×1 / 2×1 / 1×2 三档都渲染「图标 + 名称（1 行）+ 副标题（1 行）」，全部省略号截断、不折行；
- 副标题为空时显示 `点击打开`（未配置链接时显示 `未配置链接`），保证三档都有一行副标题且不伪造第三方信息；
- 没有出现「三元素全显 + 字号≥10 仍溢出」的档位，所以**未隐藏任何副标题**。

### 2.4 ≥2×2 与整卡点击
- 卡片内不再渲染任何「打开」按钮（代码层已删除 `openTarget/handleTap` 与按钮分支）；`≥2×2` 的截图 `20-entry-2x2.png` 可见只有图标/名称/副标题；
- 点击整卡由 `ScreensaverPage.handlePlayModeCardTap` → `jumpFromEntryCard` 统一处理，热区 = 整卡；
- 按下态：`ScreensaverEntryCard` 根节点在 `TouchType.Down` 时 `opacity 0.62 + scale 0.97`，抬起/取消恢复；不是动画、不是常驻动效；
- 失败提示：无链接 → toast「未配置跳转链接」；上下文缺失 → toast；`screenSaverOpenLink` 失败 → toast 失败原因（见 `ScreensaverPage.jumpFromEntryCard`）。实测用 `https://www.example.com社交社交` 拉起浏览器成功（`entry link opened` 日志），浏览器自身报 `ERR_NAME_NOT_RESOLVED`；App 侧只在 `openLink` 真正失败时 toast。

### 2.5 自定义图标链路（选图 → 解码 → 裁剪 → 沙箱 → 兜底）
1. **选图**：`photoAccessHelper.PhotoViewPicker`（系统选择器，**不新增权限**；实测弹出选择器并显示「仅可访问所选图片」，无授权弹窗）；
2. **解码**：读原图 `ImageInfo`，取中心正方形 `desiredRegion`，`desiredSize=384×384`（最大档图标 122vp × 3 倍屏 ≈ 366px，留余量）；不会把原图整张解码进内存；
3. **方形居中裁剪**：`desiredRegion` 即原图中心正方形；解码输出 384×384；
4. **打包/落盘**：`image.ImagePacker.packing(..., {format:'image/png', quality:100})` → 写 `${filesDir}/entry_icons/entry_icon_<ts>.png`；
5. **持久化**：只把沙箱 `file://` 路径写入 `entry.iconUri`，随卡片布局持久化（`ScreensaverRawEntry.iconUri`）；
6. **渲染**：`Image(uri).objectFit(Cover).borderRadius(size×0.24)`（等比 cover，不拉伸；圆角与既有中性图标 0.24 一致）；
7. **兜底**：启动时 `screenSaverEntryIconUsable` 做 `accessSync`；运行中 `Image.onError` 置 `iconBroken`；任一失败回退「名称首字」中性图标，不空白不崩溃；
8. **恢复默认**：设置面板「恢复默认」清空 `iconUri` 并删除沙箱文件；
9. **防卡死**：系统选择器异常不返回时，30s 看门狗恢复「选择图片」可点，避免永久停在「处理中…」；
10. 不写系统相册、不上传、不新增权限。

> **未验证**：模拟器相册为空，无法实际选到图片，因此「选图后的解码/裁剪/PNG 落盘/重启后仍生效/删除文件回退」只做了代码链路核对；系统选择器弹出与免权限已实测。按交付要求明确标注为「未验证」。

- 5s 轮询逻辑未改。

**修复前后验证**：
- 修复前（代码证据）：上述 ①–④ 可复现「改代码后仍显示旧名称 / 更新后闪回」。

### 3.2 屏保态点击刷新（唯一白名单例外）
- **仅** `ScreensaverPage.handlePlayModeCardTap` 的 `cardType === 'quotes'` 分支调用 `screenSaverRequestQuotesRefreshFor(cardId)`；入口/视频/其它卡片分支不变；
- **防抖**：页面 `quotesTapAt: Map<cardId, timestamp>`，同一卡片 `now - last < 1000ms` 直接合并；模型内还有 `canManualRefresh()` 的 1s 源端限频；配置签名变化时绕过点击限频（保证 3.1 立即生效）；
- **手势仲裁**：长按 `longPressAtMs` 600ms 内的补发 click 忽略；行情卡内 `CardScrollView.onUserScroll` 记录 `lastScrollAt`，滚动后 300ms 内的点击不触发刷新；
- **反馈**：右上角静态文字「刷新中… / 已刷新 / 刷新失败 / 请稍后」，成功 1.6s、失败 2s 自动消失；无动画、无常驻状态；
- **失败退避**：失败后 `pollFailures` 进入既有 15s→30s→3 次停止的退避；手动失败不清空已有数据；
- **5s 轮询**：`showHint`/`manualRefresh` 不触碰 `pollTimer`，成功后仍按原 5s 节奏；
- **实测**：`10:19:27.614 quotes request #2`，`10:19:27.918 quotes tap merged`（0.3s 内合并），`10:19:29.855 request #3`、`10:19:31.783 request #4`（均 >1s，属于合法的新点击）。

#### 3.3.2 字段映射（已实测）
| 字段 | 含义 | 本项目用途 |
|---|---|---|
| `data.<query>.data.date` | 交易日 `YYYYMMDD` | 图头日期、跨日判断 |
| `data.<query>.data.data[]` | `"HHMM price volume amount"` | 取前两段：分钟时间 + 该分钟价格 |
| `data.<query>.qt.<query>[4]` | 昨收（样例 1318.49） | 分时涨跌基准、昨收虚线 |
| `data.<query>.qt.<query>[3]` | 最新价（1335.00） | 失败时用 `[3]-[31]` 反推昨收的兜底 |
| `data.<query>.qt.<query>[31]/[32]` | 涨跌额/涨跌幅（16.51 / 1.25） | 与卡片交叉核对 |
| `data.<query>.qt.<query>[1]/[2]` | 名称/代码 | 仅日志核对，UI 用行情接口的数据 |

**数据口径**：卡片「最新价/涨跌幅」来自 `qt.gtimg.cn`（同一腾讯快照）；分时昨收来自本接口 `qt[4]`。样例 1335.00 / 1318.49 - 1 = **+1.25%**，与卡片 `+1.25%` 完全一致。容差：昨收一致；最新价可能因 5s 行情与 60s 分时快照时间差而出现 0.01 级差异，不使用第二个数据源。

#### 3.3.3 刷新与缓存（不塞进 5s 价格轮询）
- **交易时段**：**每只股票**独立定时器，间隔 `60000ms`；以各自的 `minuteLastAttemptMs` 补齐 60s，保证任意两次请求 ≥60s；不合并进 5s 价格轮询；
- **非交易时段**：不启动定时器；每只股票只在没有当日/最近交易日完整图时拉一次；后续 5s 价格轮询不会重复拉；
- **缓存**：`AppModel.minuteCache` 按 `query` 存，Preferences key `screen_saver_minute_cache`；最多 24 个标的；`fetchedAt` 超过 7 天丢弃；跨日由日期标签和交易时段判断处理；
- **失败降级**：没有完整数据 → 「分时暂不可用」/「分时数据不足」占位；已有完整数据但本次刷新失败 → 保留完整缩略图并标「缓存」，绝不画残缺折线；
- **点数**：上限 240，超出截断；不画坐标轴，图头「分时 · MM-DD」使用涨跌色，另标注「昨收」；
- **绘制**：`QuotesMinuteChart` 用 `CanvasRenderingContext2D` 自绘，只在 `revision`/尺寸/配色变化时 `draw()`，无动画；折线 + 昨收虚线 + 均价线（分钟价格累计均值）；
- **空间分配（>2×2）**：每只股票 = 名称 L4 16 + 代码 L6 12 / 涨跌幅 L4 16 + 价格 L6 12 / 缩略图固定 52vp（含「分时 · 日期」「昨收」标签）/ 条目间距 8vp；列表可上滑；底部固定 时间 L6 + 状态 L7 + 免责声明 L7（**最后一行**）。3×2 实测两条缩略图（截图 `21-quotes-3x2-thumbs.png`）。

### 3.4 编辑布局页与屏保页的分时图一致性（本轮新增）
- **问题**：`chartMode()` 原来只在 `cardMode === 'play'` 生效；长按进入「编辑布局」后行情卡退回多标列表，与屏保页不一致。

### 4.4 倒计时在线假期数据排查（本轮附加修复）
- **现象**：倒计时卡显示「假期数据加载中…」或「暂无未来标记日期」，看起来在线假期没有出现。
- **实测日志**：`holiday ok year=2026 days=39 url=https://publicapi.xiaoai.me/holiday/year?date=2026`、`holiday ok year=2027 days=0`；2026 年最后一条是 `2026-10-10 国庆节调休`，2026-10-24 之后没有未来标记；2027 年接口返回 `code=-1, data=[]`（年度公告未发布）。因此**在线请求和解析都成功，但数据源本身没有可倒计时的未来日期**，不是网络/解析 bug。
- **修复**：
  1. `ScreensaverHolidayStore.ensureCoverage()` 改为共享同一个在途 Promise；多张倒计时卡同时挂载时都等待同一请求，避免后一张卡“立即 return”后停在 loading；
  2. 空态增加 `emptyDetail`：区分「2027 年假期公告尚未发布；在线数据已加载」「在线数据已加载，暂无未来标记日期」「加载中」「请求失败」；
  3. 卡片标题从「暂无未来标记日期」改为「暂无未来假期」，避免被误认为请求失败。
- **不伪造数据**：没有把 2027 年元旦等固定日期硬编码成在线假期；如果产品需要「固定节假日兜底」，需另行确认数据口径（见未决项）。
- **截图**：`.verify/round/25-countdown-empty-state.png`（两张倒计时卡均显示最终空态，不再一张卡在 loading）。

### 4.5 倒计时：周末计入 + 法定节假日感叹号（本轮新增）
- **需求**：下一假期不再只限法定节假日，周末也计入；下一假期是周末 → 正常显示；是法定节假日 → 天数后显示感叹号。
- **计算规则**（`CountdownViewModel.ets`）：
  1. 仅 `source = auto/online` 时加入周末候选；`source = custom` 仍只显示用户自定义日期；
  2. 从今天起最多向后扫描 21 天，周六/周日均为候选；今天本身是周末时，倒计时为「就是今天」；
  3. 在线数据标记为「休」的日期（法定假日覆盖的周末）不重复生成周末条目，交给在线假日段处理，因此仍按「法定」显示感叹号；
  4. 在线数据标记为「班」的调休补班日不作为周末候选，避免把补班日算成休息日；
  5. 周末是本地日历事实：在线数据未加载/失败时仍可显示最近周末；在线数据到达后，如更近的法定假日存在，会自动替换；
  6. `ScreensaverCountdownView.isStatutory`：选中日期包含在线「休」段时为 true；周末、自定义、调休「班」均为 false。
- **UI**：`CountdownCardView.ets` 在「N 天」后追加 `!`（`restTag` 绿色、与后缀同字号，1×1 为 L7=10fp，不破 10fp 下限）；「就是今天」不显示感叹号；空态/加载态字段同步补 `isStatutory=false`。
- **实测**（模拟器改系统日期后冷启动）：
  - 2026-10-21（周三）→ 「还剩 3 天 / 周六 / 10月24日 / 休」，**无**感叹号（`.verify/round/32-countdown-weekend-upcoming.png`）；
  - 2026-09-30（周三）→ 「还剩 1 天! / 国庆节 / 10月1日–10月7日 / 休」（`.verify/round/31-countdown-statutory-relaunch.png`）；
  - 2026-10-24（周六，设备真实日期）→ 「就是今天 / 周六 / 10月24日 / 休」，无感叹号（`.verify/round/33-countdown-weekend-restored.png`）；
  - 验证后已通过「自动设置」恢复设备真实日期（`hdc shell date` = Sat Oct 24 11:32 CST 2026）。
- **注意**：§4.4 的空态截图（25）是「周末尚未计入」时的上一轮状态；本轮起 `auto/online` 会优先显示最近周末，在线无未来假期不再直接进入空态。
