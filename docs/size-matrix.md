# 尺寸矩阵与网格基准（缺陷 3）

> 网格基准来源：**工程内没有 Pixso 第 11 页导出/guid 可引用**，以下基准与全部数值均为
> **定为实现侧方案，待设计确认**。实现位置：`entry/src/main/ets/cards/CardCatalog.ets`（数据表）
> 与 `entry/src/main/ets/model/AppModel.ets`（吸附/放置）。

## 1. 统一网格基准

| 项 | 值 | 说明 |
|---|---|---|
| 列数 × 行数 | 手机 4×8；折叠屏展开 8×8；平板 12×7 | 沿用既有断点常量（`ConfigModels`） |
| 单元尺寸 | **自适应**：格宽 = 网格宽/列数，格高 = 网格高/行数（360vp 宽手机 ≈ 90×90vp） | 不写死 vp，跨设备比例一致 |
| 卡片间距（gutter） | **0vp**（卡片紧贴） | 视觉分界由「圆角 10vp + 卡面 `#0D0D10` + 1vp 12% 白细描边」承担（缺陷 2） |
| 画布边距 | **0vp**（屏保全出血）；编辑态顶/底栏各自内边距 16vp | 沿用现状 |
| 尺寸表达 | 整数跨度 `列×行`；手机档列 1..4、行 1..6 | 支持 1 行/1 列与 1×3 这类奇数跨度 |
| 吸附规则 | 先比 `|Δ列|+|Δ行|` 最小；平局取面积大者；再平局取列跨度小者 | 确定性、可测试（`screenSaverSnapCardSize`） |

## 2. 尺寸矩阵表（手机档 4×8）

密度三档含义：**minimal** 极简 / **compact** 紧凑 / **full** 完整。带「预设」的尺寸会在设置面板里显示为快捷胶囊。

| 卡片类型 | 允许尺寸（列×行） | minimal | compact | full | 约束与理由 |
|---|---|---|---|---|---|
| 时钟 | 1×1, 2×1*, 3×1, 4×1, 1×2, 1×3*, 2×2, 2×3, 4×2*, 4×3*, 4×4* | 1×1/2×1/3×1/1×3：**仅时间**一行 | 4×1/1×2/2×2：时间 + 一行日期（≥3 列带星期） | 2×3/4×2/4×3/4×4：时间 + 日期·农历（+星期），遵循 `clock.format` | 多行信息需要行高；1×1≈90×90vp 只容一行大字；字号地板不会超过「宽度能放下的字号」，避免截断 |
| 相册 | 1..4 × 1..6 **全部**（含 1×1*、1×3*、2×2*、4×4*） | 1×1/2×1/1×2/1×3/1×4/1×5/1×6：仅图片（隐藏信息条与占位文案） | 3×1/2×2*/2×3/3×2：图片 + 信息条（字号 9） | 其余（如 4×2/3×3/4×4）：图片 + 信息条（字号 10）+ 既有占位/权限提示 | 纯图像对任意矩形都成立（Cover 裁剪），因此放开区间全域；文字需要宽度 |
| 视频 | 1..4 × 1..4 **全部**（含 1×1*、1×3*、2×2*、4×3*） | 1×1/2×1/1×2/1×3/1×4/3×1/4×1：封面帧 + 播放/暂停角标（无文字） | 2×2/3×2/2×3：封面 + 角标 + 单行状态（未选择/文件名） | 其余（如 4×3）：封面或播放画面 + 完整占位与编辑态「重选」 | 上限 4×4 是**功耗约束**（解码面积越大越耗电），非视觉原因 |
| Git 贡献 | 1×1, 2×1, 1×2, 1×3, 4×1, 2×2, 3×2, 2×3, 4×2*, 4×3*, 4×4* | 1×1/2×1/1×2/1×3：**总提交数 + 近 7 天迷你条**（无标题/页脚） | 4×1/2×2/3×2/2×3：标题 + 热力图（展示周数自动压到 12 周）+ 无页脚 | 4×2/4×3/4×4：标题 + 用户周数热力图 + 页脚 | 热力图每格代表一天，<2×2 时格子不可辨认，故降级为数字摘要而不是空白 |
| 天气（需求 A） | 1×1*, 2×1, 1×2, 1×3, 1×4, 2×2*, 3×2, 2×3, 3×3, 4×1, 4×2*, 4×3*, 4×4* | 1×N：只显示温度 | 2×2/3×2/2×3/3×3/4×1：温度 + 天气描述 + 当日高低温 | 4×2/4×3/4×4：温度 + 描述 + 高低温 + 城市 + 数据源署名 | 小尺寸只留信息量最高的数字；署名要求（Open-Meteo 条款）在完整档可见 |
| 应用入口（需求 A） | 1×1*, 2×1*, 1×2, 4×1, 2×2*, 2×3, 3×2, 4×2* | 1×1/2×1/1×2：名称首字/短名（1×1 放不下按钮） | 4×1/2×2/2×3/3×2：名称 + 副标题 + 「打开」按钮 | 4×2 及更大：同 compact（按钮 + 名称 + 副标题），条目更宽松 | 1×1≈90vp 放不下按钮；跳转按钮只在编辑态出现（播放态保持屏保纯净） |

`*` = 该尺寸带设置面板快捷胶囊。

## 3. 数据驱动规则（不是散落的 if-else）

```
ScreensaverCardSizeSpec {            // 每类卡片一张
  minColSpan/minRowSpan/maxColSpan/maxRowSpan
  entries: ScreensaverCardSizeEntry[] // { colSpan, rowSpan, density, presetLabel }
}                                     // (0,0) 行 = 兜底行：区间内其余矩形合法且取该密度
```

| 纯函数 | 作用 |
|---|---|
| `screenSaverIsSizeAllowed(type, c, r)` | 合法性判定（有兜底行的类型 = 区间内任意矩形；无兜底行 = 只认表内精确跨度） |
| `screenSaverSnapCardSize(type, c, r, maxC, maxR)` | 非法尺寸吸附到最近合法值（规则见 §1），读盘时也走它，旧数据里的非法跨度会自动纠正 |
| `screenSaverResolveDensity(type, c, r)` | 尺寸 → 内容密度档；卡片视图只依赖它决定「显示多少内容」 |
| `screenSaverSizePresets(type)` | 从矩阵里筛出快捷胶囊，面板不自己维护尺寸清单 |

视图侧：各卡片视图**自己**按 `card.colSpan/rowSpan` 查表（而不是父层经 `@Builder` 透传），因为 `@Builder` 多参数按值传递、ForEach 复用时不刷新，实测会出现「尺寸变了内容不变」。

## 4. 交互规则（编辑态）

1. **实时预览**：拖拽缩放的预览跨度直接写回卡片（`@Trace`），格子与卡片内容随手指实时变化；预览与提交共用同一套吸附计算（`targetSpanFor`），保证「预览看到的尺寸 = 松手落到数据里的尺寸」。
2. **吸附反馈**：尺寸标签显示 `3×1 → 2×1 已吸附`；提交时若吸附过，toast「已吸附到 2×1」。
3. **越界**：目标跨度先按网格边界回拉起点，保证整卡可见。
4. **重叠**：预览期间整卡描红边；松手回滚到拖动前的矩形并 toast「尺寸不可用：与其它卡片重叠或越界，已恢复原尺寸」。
5. **最小/最大**：由各卡片矩阵表单一约束（如视频上限 4×4 = 功耗约束）。
6. **面板尺寸胶囊**：时钟/Git/天气/入口等按矩阵提供的预设显示；相册/视频同样提供 1×1/1×3 等档位。

## 5. 已知限制

- **宽屏播放态**：折叠屏/平板播放时走 `reflowForColumns` 重排，内容密度按**存储跨度**计算，可能与重排后的实际尺寸略有偏差（正常，不影响可用性）。
- 面板「尺寸」胶囊是快捷入口；**任意**合法跨度（含 1×3 这类奇数跨度）仍以编辑态拖拽缩放为准。
