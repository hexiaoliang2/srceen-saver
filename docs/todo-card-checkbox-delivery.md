## 0. 先报告：规格与既有实现的冲突 / 取舍

### 0.1 §1.4「热区必须 ≥44×44vp」与 §1.5 / §6.2 冲突

实测改造前单行行距 **75px = 23.08vp**，圆右侧约 **2.5vp** 就是行文字；相邻行热区若做到 44vp 高，必然重叠并可能勾错行。要同时满足 44×44、行高/行距不变、热区不覆盖文字且相邻不重叠，在本卡片尺寸下**数学上不可能**。

本轮按以下优先级取舍（已写进 `CardTheme.ets` 注释）：

1. 不误勾行（相邻热区不重叠）；
2. 点文字/空白无动作（热区不覆盖文字）；
3. 行高、行距、文字起始缩进不变；
4. 热区尽量大。

最终热区：**19vp 宽 × 23vp 高**（常规字号）/ **19vp × 21vp**（minimal 档），范围是「卡片左边缘 → 圆右缘」× 整行高。**未达到 44×44vp**，这是明确报告的未满足项，不是静默降级。

### 0.2 §2.2「1×1 保留原装饰小点、已完成项沉底并显示删除线」与既有实现冲突

既有 1×1 待办卡**不是列表**，而是计数卡：显示「未完成数量 / 共 N 条」，没有任何装饰小点，也没有可承载删除线的条目。若为满足本条而把 1×1 改成列表，会违反硬约束 4「保持现有外观与行为」。

本轮处理：**1×1 完全保持既有计数外观与行为**，不渲染空心圆/只读圆，点击无动作；数据层仍把已完成项排在列表末尾，但 1×1 不展示条目，因此 1×1 上看不到删除线。该条按冲突报告，未用「看起来能点但点不动」的圆充数。

### 0.3 §4.6 重排动画：选择 0ms 即时跳变

规格写的是「允许一次 ≤300ms 的位移过渡」，不是强制。本轮选择**即时跳变**（0ms）：

- 天然满足「≤300ms、只播一次」；
- 天然满足「系统减弱动态效果时直接跳变」；
- 不新增常驻动画，也不需要在渲染路径读取系统动效开关。

因此未调用 `accessibility.isAnimationReduceEnabledSync()`（API 23 起存在）；因为没有动画路径，减弱动效分支是 no-op。若产品要求必须看到位移过渡，需要另开一轮并接受额外的 1 次/点击动画。

### 0.4 §3.6 点击后不重置滚动位置：已做，但不在可视区时不主动追随

- 用 `ForEach` + 稳定 item id 差量更新，替代原先 `LazyForEach.onDataReloaded`（后者会把 List 拉回顶部）。
- 勾选前记录 `Scroller.currentOffset().yOffset`，更新后通过**一次性 `FrameCallback`**（不是 `setTimeout`）在下一帧无动画 `scrollTo` 还原。
- 实测记录到切换前偏移 **36.44vp**；切换后首行仍按原偏移被裁切，未回到顶部（`50-scroll-offset36.png`）。
- 取舍：被移动的条目若已不在可视区，**不主动滚动到它的新位置**（规格为可选）。保留用户当前阅读位置，避免突然跳走。

### 0.5 竖屏 / 横屏既有架构是两套独立布局

工程既有实现中竖屏与横屏各存一份布局，横屏首次生成时会给卡片分配新的 card id。若待办数据只挂在 `card.todo` 上，换方向后必然出现两份副本。

本轮新增 `todo.listId`：横屏快照原样复制 listId；装载完成后把 listId 相同的卡片指向**同一个 `ScreensaverTodoConfig` 对象**。旧数据没有 listId 时：

- 非空列表用首条 item id 生成 `todolist_legacy_<itemId>`（横屏克隆保留 item id，可自动配对）；
- 空列表用 `todolist_legacy_<cardId>`，再按待办卡出现顺序做一次保守配对；
- 已分叉的旧数据（两边 item id 不同）不强行合并，避免丢条目。

### 0.6 既有「清除已完成」按钮

屏保展示层**全部显示、不折叠、不隐藏、不限制条数**。设置面板里既有的「清除已完成」是用户显式删除操作，不是渲染层自动隐藏；本轮保留该既有能力，未改成自动删除。

## 2. 数据结构变更与迁移

### 2.1 严格模型（v2）

```ts
ScreensaverTodoConfig {
  version: 2,
  listId: string,          // 竖屏/横屏共享同一份数据的身份
  items: ScreensaverTodoItem[]
}

ScreensaverTodoItem {
  id: string,
  text: string,
  orderIndex: number,      // 原始顺序（取消完成回原位的依据）
  completed: boolean,
  completedAt: number | null
}
```

### 2.2 Raw 结构

```ts
ScreensaverRawTodo {
  version?: number,
  listId?: string,
  items?: ScreensaverRawTodoItem[]
}

ScreensaverRawTodoItem {
  id?, text?,
  orderIndex?, completed?, completedAt?,
  done?                    // v1 兼容；v2 写盘时作为 completed 的镜像
}
```

### 2.3 v1 → v2 迁移（`AppModel.applyRawTodo`）

1. `completed = rawItem.completed ?? rawItem.done ?? false`（新字段优先，旧 `done` 不会丢）；
2. `orderIndex` 缺失 → 原始数组下标；解析后按 orderIndex 稳定排序并重新编号 0..n-1；
3. `completedAt` 缺失且已完成 → `rawIndex + 1` 作为迁移哨兵，保证旧已完成项保持原有相对顺序，且新完成项（Date.now）永远排在其后；
4. `listId` 缺失：非空列表 `todolist_legacy_<首条 item id>`；空列表 `todolist_legacy_<cardId>`；
5. `version` 固定写 2；检测到迁移后置 `todoMigrationDirty`，装载结束落盘一次；
6. 文本仍裁剪到 60 字、最多 100 条——与旧版本规则一致，不新增条目丢失路径。

### 2.4 兼容性验证方式与结果

- 测试前在模拟器 Preferences 中注入 v1 原始数据（6 条：4 未完成 + 2 个 `done:true`，没有 orderIndex/completed/completedAt/listId），并额外注入一个 1×1 待办卡（3 条）。
- 启动后 6 条全部出现；2 个旧 `done:true` 显示为已完成并沉底，无条目丢失。
- 重新拉取 Preferences 验证：`version=2`、`listId=todolist_legacy_todo_seed_1`、`orderIndex=0..5`、`completed` 正确、`completedAt` 为迁移哨兵 2/5；再次启动不再重复迁移。
- 结论：**旧数据升级不丢、状态与顺序可保持**。

## 3. 排序规则

### 3.1 两个分区与排序键

- 未完成区：`orderIndex` 升序；
- 已完成区：`completedAt` 升序（先完成的在上，新完成的追加到最末）；
- 分区内部平局用 id 兜底，保证确定性；
- **全部显示**：不限制条数、不折叠、不隐藏。

### 3.2 稳定性保证

- `config.items` 永远保持原始条目顺序；展示数组由 `screenSaverTodoDisplayItems()` 按**持久化键**计算；
- 渲染路径不读取 `Date.now()`，不会因时间推移产生抖动；
- 完成时间用 `max(Date.now(), maxCompletedAt + 1)`，连续快速完成也不会出现相同 completedAt 导致的顺序抖动。

### 3.3 勾选 / 取消的实现

- 勾选：`completed=true`、`completedAt=单调时间戳`；`orderIndex` 不变；展示层把它放到已完成区末尾；
- 取消：`completed=false`、`completedAt=null`；`orderIndex` 不变；展示层按原 orderIndex 回到未完成区原位（**不会追加到末尾**）；
- 手动上移/下移：交换数组位置后按数组顺序重排 orderIndex 0..n-1；
- 新增：orderIndex = 当前最大值 + 1。

## 5. 交互与持久化实现

### 5.1 只有圆可点

- `TodoCheckCircle` 只在 `cardMode === 'play' && showList() && cardActive && enabled` 时 `interactive=true`；
- 非展示态 `HitTestMode.None`，触摸穿透给卡片（编辑态仍可选中/打开设置）；
- `ScreensaverPage.handlePlayModeCardTap` 增加 todo 分支：设置 `cardActionAtMs` 后直接返回，因此点击卡片其他位置/文字/空白不会唤出胶囊、不会跳转；点击圆本身只触发勾选。
- 1×1 不渲染该组件，点击卡片同样走 todo 分支无动作。

### 5.2 连点与防误勾

- 整卡级冷却窗口 320ms：勾选后条目立即下沉，若允许同位置再次点击会落到补位上来的另一条；冷却窗口内忽略整张卡片的所有勾选点击。
- 实测两次 uinput 点击间隔约 100ms：只翻转第一条，第二条保持未完成（`F6-double-tap-once.png`）。

### 5.3 持久化

- 每次勾选/取消：先改内存 → 立即刷新 UI → `screenSaverAppModel.save()` + `flush()` 立即写盘（不等 200ms 防抖）；
- 竖屏/横屏共享对象，`flush()` 写两个方向 key；
- 重启验证：`F7-restart-persisted.png` 与重启前状态一致（4 未完成 / 2 已完成）。

### 5.4 滚动位置

- `ForEach` + 稳定 id 差量更新；
- 勾选前记录 `currentOffset().yOffset`；
- 下一帧 `FrameCallback`（一次性，不驻留）无动画 `scrollTo` 还原；
- 实测偏移 36.44vp 被保留：`50-scroll-offset36.png` 中列表首行仍按原偏移裁切，没有回到顶部；
- 若被移动条目在可视区外，不主动追随（规格可选），保留当前阅读位置。

### 5.5 无障碍

- 未完成：`accessibilityText('未完成，点击标记完成')`；
- 已完成：`accessibilityText('已完成，点击取消完成')`；
- `accessibilityChecked(completed)`、`accessibilityRole(CHECKBOX)`、展示态 `accessibilityLevel('yes')`；
- 非展示态 role 为 CIRCLE、level 为 no；
- 未做自定义焦点样式，沿用平台默认焦点（未用屏幕朗读实测，见未验证清单）。

## 8. 未验证清单

1. **真机**：只在 Mate 80 Pro Max 模拟器验证，未在物理设备实测触控/性能/无障碍；
2. **屏幕朗读/TalkBack**：`accessibilityText/Checked/Role` 已实现，但未用读屏服务验证播报与焦点顺序；
3. **全部尺寸档**：1×1、1×2、2×1、2×2 已实测；3×1/4×1/3×2/4×2/2×3/3×3/4×3/2×4/3×4/4×4 共用同一代码路径，但未逐档截图；
4. **44×44 热区**：未实现（冲突报告），实际热区 19×23 / 19×21；
5. **1×1 的已完成删除线**：既有 1×1 是计数卡，无法展示（冲突报告）；
6. **重排位移动画**：未实现，选择 0ms 跳变；
7. **系统「减弱动态效果」**：未调用读取接口；因无动画路径，行为恒为跳变，未做系统开关对照实测；
8. **100 条压力/长时间运行**：实测最多 10 条；未测 100 条上限、长时间滚动、低电量场景；
9. **浅色/复杂背景自动墨色**：颜色走 `cardTone`/palette，但截图环境为纯黑背景；未在浅色背景、图片背景逐档验证圆的对比度；
10. **精确 100ms 响应**：主观即时、无可见延迟；未做帧级/日志级耗时统计；
11. **多指/边缘手势/无障碍焦点框**：未专项验证。

## 9. 验收标准对照

|---|---|
| 空心圆可点；完成后移到未完成项之后、已完成区最末位；删除线 | **通过**（`F4`） |
| 再次点击已完成圆可取消；回原位并恢复未完成样式 | **通过**（`F5`） |
